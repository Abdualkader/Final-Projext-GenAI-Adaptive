Topic 1: Architecture & Design Implementation 02 / 14

Three-Tier Architecture & Clean Design

Strict separation of presentation, serverless logic, and cloud persistence with zero client-side credential exposure.

Three-Tier Architectural Model
  • Presentation Tier: Flutter Mobile & Web Client with reactive Provider state management and sensory-friendly UI components.
  • Application Logic Tier: Firebase Cloud Functions hosting the Item Response Theory (IRT) difficulty engine and AI Prompt Gatekeeper.
  • Data Tier: Cloud Firestore (NoSQL document database) and Firebase Cloud Storage (high-clarity audio and image assets).
Zero Key Exposure Rule (Security)
  • Private Generative AI API keys are strictly forbidden from client binaries and assets.
  • All prompt orchestration, response parsing, and validation run server-side behind authenticated Cloud Functions.

Topic 3 & 8: Security Architecture & Access Control 05 / 14

Server-Side Security & Data Privacy

Granular rule-based access constraints protecting neurodivergent student data privacy.

Cloud Firestore Security Rules (firestore.rules)
  • Account Privacy: request.auth.uid == userId strictly blocks parents from inspecting or modifying unrelated user accounts.
  • Child Data Scoping: request.auth.uid == resource.data.parentId enforces that child profiles, sessions, quiz logs, and progress are restricted strictly to authorized parents.
  • Content Protection: Learning categories and vocabulary cards are read-only for authenticated learners; write/delete operations are forbidden.
Cloud Storage Security Rules (storage.rules)
  • Educational media (images, audio pronunciation) readable by authenticated users.
  • Upload and overwrite permissions blocked for client accounts.
Client Navigation RouteGuard
  • Protected Routes: /parent/child-selection, /parent/dashboard, /parent/settings.
  • Open Child Routes: /child/home, /child/learning, /child/quiz.
  • Unauthenticated navigation attempts are automatically intercepted and routed to the secure login barrier.

Topic 4: Frontend & Sensory UI/UX Implementation 06 / 14

Sensory-Calibrated Design System

Engineered specifically for neurodivergent cognitive profiles and sensory sensitivities.

Calm Pastel Palette (Sensory Safety)
  • Soft Sky Blue (#E8F4F8): Primary peaceful background tone reducing ocular fatigue.
  • Mint Green (#E8F8F5): Gentle affirmation color for successful interactions.
  • Warm Amber (#FFF8E7): Supportive guidance indicator replacing harsh red error states.
  • Slate Typography (#1A2B3C): High-contrast readable text with zero glare.
Elimination of Sensory Triggers
  • No Strobing or Rapid Flashes: All transitions use smooth easing (≥400 ms).
  • No Punitive Buzzers: Wrong answers trigger encouraging gentle chords.
  • Gentle Phrasing: "Let's try again gently! 🌱" instead of "Wrong Answer!".
Motor & Cognitive Ergonomics
  • Enlarged Touch Targets: All buttons and interactive flashcards adhere to ≥64×64 dp targets to support developing fine-motor coordination.
  • Predictable Layouts: Fixed button positions (Next/Back/Audio) create cognitive security and spatial familiarity.
  • Zero Cognitive Clutter: Clean, focused views with zero third-party ads, moving tickers, or distracting decorative graphics.

Bug 1: Arabic Diacritics (Tashkeel) String Matching

Issue: Substring search failed on words like 'قِطَّة' due to Unicode diacritic characters (Kasra \u0650).
Fix: Engineered diacritical normalization across vocabulary search queries.

Bug 2: Headless Unit Test Firestore Initialization

Issue: Headless flutter test runs lacked default Firebase apps, throwing unhandled exceptions.
Fix: Implemented resilient in-memory fallback state in all repository write methods.

Bug 3: Dynamic RTL Layout Flipping & Overflow

Issue: Rapid toggling between Arabic and English caused text clipping on compact viewports.
Fix: Wrapped titles in responsive LayoutBuilder and Directionality widgets.
